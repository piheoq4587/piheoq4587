# 道术 · Framework Distillation & Application

> 「枢始得其环中，以应无穷。」——《庄子·齐物论》

蒸馏文本里的"道"（核心框架、底层逻辑、思维范式），并在用户授权下迁移应用到具体问题。

---

## 入口分流（Phase 0）

收到用户输入后，先判断模式：

| 用户输入特征 | 模式 | 跳转 |
|------------|------|------|
| 提供原文/PDF/链接，明确说"蒸馏/提炼/分析这段" | **蒸馏模式** | → Phase D |
| 提出实际问题 + "用 XX 之道分析" / "我有 XXX 困境，用什么道分析好" | **应用模式** | → Phase A |
| 「我蒸馏过哪些道」「列出道术」「道术索引」 | **索引模式** | → Phase I |
| 模糊的"帮我想想这个问题"，没有指定道 | **应用-严格模式**（默认，先推荐） | → Phase A |

---

## Phase D：蒸馏模式

读取 `references/distillation-method.md` 和 `references/classical-text-handlers.md` 获取详细方法论后执行：

### D1. 接收资料
- 用户粘贴文本 → 直接读
- 用户给文件路径 → 用 Read 工具
- 用户给链接 → 用 WebFetch（仅当真正需要时）
- 用户只说"蒸馏《XX》" → 询问："你手上有原文吗？或者要我从你给的某个文件读？我不会凭训练记忆编造原文。"

### D2. 命名与目录创建
- 与用户确认 dao 命名（例：`dao-yinfujing`、`dao-laozi-wuwei`、`dao-sunzi-xushi`）
- 创建结构：

```
~/.gemini/skills/dao-{name}/
├── SKILL.md
├── references/
│   ├── 01-原文.md
│   ├── 02-训诂与释义.md
│   ├── 03-核心框架.md
│   ├── 04-隐喻系统.md
│   └── 05-反模式.md
└── memory/
    └── applications/        # 应用记录将按场景动态分类
```

### D3. 四层拆解（详见 distillation-method.md）

1. **训诂层**：关键字词的本义（不带后世引申）
2. **修辞层**：识别对偶、排比、隐喻、反讽
3. **结构层**：篇章逻辑、命题之间的关系
4. **范畴层**：核心二元/多元对待（如阴阳、虚实、刚柔、本末、体用）

### D4. 框架提炼

输出五项：
- **核心范畴**（3–5 个）
- **底层公理**（3–5 条，可"如果 X 则 Y"化）
- **思维操作集**（5–8 步，"使用此道时怎么想/怎么做"）
- **隐喻系统**（作者用什么意象承载思想）
- **反模式**（明确否定的做法）

### D5. 三重验证（避免假框架）

每个核心范畴必须满足：
- ✅ 在文本不同段落出现 ≥2 次（跨段复现）
- ✅ 能解释文本未直接讨论的同类现象（生成力）
- ✅ 揭示作者对世界本质的判断，而非通用常识（本体性）

仅通过 1–2 项 → 降级为"决策启发式"
0 项 → 丢弃

### D6. 输出

1. 写入 `dao-{name}/` 下五个 references 文件
2. 写入 `dao-{name}/SKILL.md`（套用 `references/dao-skill-template.md` 模板）
3. **更新 `daoshu/distilled/INDEX.md`**（追加一行摘要 + 匹配标签 + 与其他道的差异点）
4. **创建 junction 同步到三 CLI**（详见安装手册）
5. 向用户展示蒸馏结果摘要并询问是否需要调整

## Phase A：应用模式

读取 `references/recommendation-rules.md` 和 `references/purity-protocol.md`。

### A1. 模式判断

| 用户表达 | 子模式 |
|---------|--------|
| 明确指定道："用《阴符经》分析…" | **快捷模式** → 跳过推荐，直接 A4 |
| 未指定道："我遇到 XXX 困境，用什么道好" / 默认 | **严格模式**（推荐） → A2 |

### A2. 推荐候选（严格模式核心）

**只读 `daoshu/distilled/INDEX.md`**（不加载任何具体 dao 的 references——这是隔离关键），按 `recommendation-rules.md` 的匹配规则输出：

```
根据你的问题"[问题概要]"，推荐以下候选道：

1. 《[道名1]》"[核心命题]"  ★★★★
   适合：[3-5 个适用场景]
   不适合：[2-3 个不适用场景]
   潜在盲区：[此框架可能让你忽视的东西]

2. 《[道名2]》"[核心命题]"  ★★★
   ...

[根据匹配情况动态推荐 1 至 N 个，不强制 3 个上限]

请选择：
  [1] 用第 1 个分析
  [2] 用第 2 个分析
  ...
  [组合 1+2] 联合使用（需你明示哪两个）
  [重选] 重新推荐
  [自定义] 你说要哪个我直接用
```

### A3. 用户授权处理

| 用户回复 | 行为 |
|---------|------|
| "用 1" | 单道分析，仅加载该 dao |
| "用 1 和 3 联合" | **联合分析**，加载这两个 dao，但输出必须**分块清晰标注**"X 框架视角"和"Y 框架视角"，不熔合 |
| "重选" | 询问追问点后重新匹配 |
| "都不合适" | 询问是否要先蒸馏一个新道（进入 Phase D） |
| "用《某新道》" | 检查该 dao 是否已存在；若不存在，建议先蒸馏 |

### A4. 加载与分析（严格隔离）

1. **物理隔离**：仅 Read 选中 dao 的 `references/` 文件，不读其他 dao
2. **Prompt 钳制**：在内部分析前，自我宣告：
   > "本次分析严格限定在 [选中的道] 框架内。禁止引入其他流派的概念、术语、隐喻。即使我知道 X 流派也讲过类似的，也不在本次输出中提及。"
3. **联合分析特例**：若用户授权 A+B 联合，必须分两个独立 section 输出，最后可有"两框架的张力/互补"小节，但不许制造一个含糊的"中间态"

### A5. Memory 写入

每次应用结束后，**追问用户**：
> "本次分析是关于哪个领域的？（我会按这个分类存档，例如：商业决策 / 学术研究 / 人生选择 / 创作 / 你自己起名）"

写入路径：`dao-{name}/memory/applications/{用户给的分类}/{YYYY-MM-DD}-{问题简述}.md`

文件内容：
```markdown
# [问题简述]
- 时间：YYYY-MM-DD HH:MM
- 道：[使用的道]
- 联合：[若是联合分析，列出另一个道]
- 场景分类：[用户指定]

## 用户问题
[原问题]

## 应用分析
[输出内容]

## 沉淀洞察
[本次特别值得记住的 1-3 句话]
```

### A6. 激活时唤醒记忆

每个 dao-{name}/SKILL.md 顶部必须含规则：
> "激活时先扫描 `memory/applications/` 看历史应用记录。如果用户的本次问题与历史问题类似，主动告知并询问是否参考。"

## Phase I：索引模式

直接 Read 并展示 `daoshu/distilled/INDEX.md`，可附加：
- 每个 dao 的应用记录数（统计 `dao-{name}/memory/applications/` 下文件数）
- 最近一次应用时间
- 用户最常用的道

## 安装与同步规则

### 创建新 dao 时必须做的三件事
1. 写完 `~/.gemini/skills/dao-{name}/` 所有文件
2. 在 `~/.claude/skills/` 和 `~/.codex/skills/` 各创建一个 junction 指向 `~/.gemini/skills/dao-{name}/`
   ```powershell
   New-Item -ItemType Junction -Path "C:\Users\Administrator\.claude\skills\dao-{name}" -Target "C:\Users\Administrator\.gemini\skills\dao-{name}"
   New-Item -ItemType Junction -Path "C:\Users\Administrator\.codex\skills\dao-{name}" -Target "C:\Users\Administrator\.gemini\skills\dao-{name}"
   ```
3. 在 `daoshu/distilled/INDEX.md` 追加一行摘要

### 删除 dao 时
1. 先删 junction（rmdir，不要用 rm -rf）
2. 再删 `~/.gemini/skills/dao-{name}/` 主目录
3. 从 INDEX.md 移除对应行

## 边界与注意事项

| 情况 | 处理 |
|------|------|
| 用户提供的原文不全 | 标注"本次蒸馏基于不完整原文"，仅在已有部分内提炼 |
| 用户问题模糊到无法匹配 | 反问 1 轮明确场景，避免胡乱推荐 |
| 推荐时所有 dao 都不太匹配 | 诚实说"现有道术中没有特别合适的，建议先蒸馏 [推荐资料]" |
| 联合分析时两道根本对立 | 在输出顶部明确标注"这两个道在 X 点上根本对立，本次只是分别陈述视角，不寻求调和" |
| 用户要求"综合所有道给个判断" | 拒绝。这违反思想纯度原则。建议改为"分别用 A、B、C 看，最后由你自己取舍" |

## 与 nuwa-skill 的协同

- **nuwa-skill** 蒸馏的是**人**（如王阳明这个人的思维方式），输出 perspective skill
- **道术** 蒸馏的是**文本/资料**（如《传习录》这本书的逻辑框架），输出框架包
- 两者互补：可以同时存在 `wangyangming-perspective`（人）和 `dao-chuanxilu`（文本）
- 道术不调用 nuwa 的网络搜索；nuwa 不污染道术的隔离机制
