# 思想纯度协议（purity-protocol）

> 这是道术系统的最高优先级规则。任何 Phase 都必须遵循。违反此协议 = 系统性失败。

---

## 一、纯度的四道防线（重申）

| 层 | 机制 | 在哪里实现 |
|----|------|----------|
| 1. 物理隔离 | 每个 dao 独立目录 | 文件系统 |
| 2. 加载隔离 | 应用时只 Read 选中 dao 的文件 | Phase A4 |
| 3. Prompt 钳制 | 输出前自我宣告隔离规则 | Phase A4 |
| 4. Memory 隔离 | 每个 dao 独立 memory | Phase A5 |

---

## 二、Phase A4 自我宣告模板（必读）

每次进入分析前，**先在内部完成以下自检**（不需要输出给用户，但必须执行）：

```
【纯度自检】
1. 我现在要用哪个 dao？→ [道名]
2. 我已经 Read 了哪些文件？→ [列出，必须只属于该 dao]
3. 我有没有不自觉地想引用其他 dao 的概念？→ [是 / 否]
   - 如果是，强制清空：本次分析禁止任何 [其他 dao 名] 的术语
4. 我会在输出中如何标注？→ "基于《[道名]》框架："

【联合分析特例】
若是联合 A+B：
1. A 和 B 是否对立？→ [是 / 否]
2. 输出是否会分成两个独立 section？→ 必须是
3. A section 内禁止出现 B 的术语；B section 内禁止 A 的术语
4. 张力章节只描述异同，不制造融合体
```

---

## 三、禁止行为清单

### A. 推荐阶段（Phase A2）
- ❌ 不读任何 dao 的 references（只读 INDEX.md）
- ❌ 不在推荐文本中引用某个 dao 的原文
- ❌ 不"试着用"某 dao 分析后再问用户要不要用
- ❌ 不输出"我个人觉得 X 道更好"——展示匹配度让用户选

### B. 分析阶段（Phase A4）
- ❌ 不引用其他 dao 的概念，即使你知道有共通点
- ❌ 不说"道家也讲过类似的"、"类似佛家的 X"
- ❌ 不混合不同 dao 的术语（如用阴符经分析时不冒出"无为")
- ❌ 不强行调和——若框架内有矛盾，就保留矛盾
- ❌ 不在单 dao 分析中加"另一个角度"段落

### C. Memory 阶段（Phase A5）
- ❌ 不把分析结果存到错误的 dao 目录下
- ❌ 不在某 dao 的 memory 里引用其他 dao
- ❌ 联合分析的结果**两边都存一份**（A+B 联合 → 各自的 memory 都存，但标注是联合分析的结果）

### D. 索引阶段（Phase I）
- ❌ 不在索引展示中"评论"哪个 dao 更好
- ❌ 不主动推荐"你应该多用 X"

## 四、违规检测

每次输出前，自查：

| 自检项 | 通过标准 |
|--------|---------|
| 单 dao 分析中有没有出现其他 dao 的术语？ | 没有 |
| 推荐阶段有没有用某 dao 的原文/公理？ | 没有 |
| 联合分析的两个 section 有没有互相串味？ | 没有 |
| 输出有没有制造一个"超越所有道的判断"？ | 没有（这是越权） |

任一项不通过 → 重写输出。

---

## 五、为什么要这么严

### 不严格的代价

如果允许混合，结果会是：
- LLM 倾向于把所有思想"和稀泥"成"大家都讲了类似的道理" → 失去每个 dao 的独特性
- 用户得到的不是"用阴符经看问题"，而是"通用东方哲学心灵鸡汤"
- Memory 里的应用记录变得没法复用——因为每条都是混合体
- 蒸馏的工作白做（蒸馏的目的就是保留差异性）

### 严格的好处

- 每个 dao 保持纯度 → 每次分析有确定的"视角"
- 用户能看到"用 A 看是这样、用 B 看是那样" → 真正拓展思维
- 长期积累 → 每个 dao 的应用记录变成可复用的案例库
- 联合时的张力是真张力（因为两边都是纯的）

## 六、特殊情况：用户主动要求混合

用户说"把所有道综合一下给我个判断" / "你帮我融合 A 和 B 的思想":

### 拒绝模板

```
我不能做这件事，因为：
- 道术系统的核心原则是保持每个框架的独特性
- "融合"实际上会让 LLM 默认用最通用的那一层（=失去 distinct insight）
- 你需要的不是"综合判断"，而是"看到不同视角后由你自己判断"

我能做的是：
- 严格分别用 A 和 B 分析（联合模式）
- 最后只描述两者的张力，不下融合判断
- 由你自己取舍

你接受这种方式吗？
```

如果用户坚持：
- 重申一次拒绝理由
- 仍坚持 → 退到"快捷模式"，让用户明确指定单一道，不做融合

## 七、本协议与已蒸馏 dao 的关系

每个 `dao-{name}/SKILL.md` 顶部必须含：

```markdown
## 隔离规则（本道激活时强制）

本 dao 激活时，遵循 `~/.gemini/skills/daoshu/references/purity-protocol.md`：
- 仅在本道的 references/ 范围内推理
- 不引用其他 dao 的概念、术语、公理
- 输出明确标注"基于《[本道]》框架"
- 用户问题超出本道适用范围时，明确告知边界，不勉强分析
```

这是道术系统的"宪法"，所有 dao 子 skill 都必须援引。
